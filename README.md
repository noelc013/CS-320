# CS-320
J-Unit Testing Studies
I can ensure that my code, program, or software is functional and secure through a few different methods. First, focusing on OOP principles is a great way to retain functionality within the code as it allows for easier alterations and updates in the future. When creating the code, it is best practice to test every handful of lines so as to catch a mistake soon after it is made. Once the code is done though, it is still important to test the functionality, even if the code is executing perfectly. We want to make sure it is not only written correctly but executing the way that was intended. This is where JUnit testing comes in. 

I interpret user needs and incorporate them into my program by gathering information on the requirements expected by the user. Once those requirements are determined, they then need to be broken down into smaller tasks that can be created and tested to ensure that we meet the user's expectations

I approach designing software by first understanding the purpose of the code or program then planning out the features and flow path, often via pseudocode or flowchart, then creating the code modularly step by step in accordance to the steps outlined in these plans.
